# Unofficial Abilities for Yoast SEO

Turns [Yoast SEO](https://wordpress.org/plugins/wordpress-seo/) into a full-coverage MCP
surface. It registers abilities via the WP Abilities API, which
[Agent Connector for WP](https://github.com/soflyy/agent-connector-for-wp) auto-exposes as
MCP endpoints — with permission checks, domain-lock, and audit logging injected for you
(this pack contains **no** auth code).

Generated by the [`wp-mcp-generator`](https://github.com/soflyy/agent-connector-for-wp/tree/master/abilities-generator) skill.

- **Requires:** `agent-connector-for-wp`, `wordpress-seo`. Target Yoast SEO (free) v27.x.
- **Vendor namespace:** `yoast/…`

Yoast core already ships three read-only analysis abilities under the `yoast-seo/…`
namespace (`get-seo-scores`, `get-readability-scores`, `get-inclusive-language-scores`).
This pack **complements** them with the write/control surface a human admin actually uses;
it does not duplicate them.

## What an agent can do

Everything a human admin can do in Yoast SEO (free) — through task-level verbs that take
only the delta you care about:

- **Per-content SEO** (posts/pages **and** taxonomy terms):
  - `yoast/find-content` — discover posts or terms + a summary of their SEO state.
  - `yoast/get-content-seo` — read the full SEO metadata for one post or term.
  - `yoast/update-content-seo` — change any subset of: focus keyphrase, SEO title, meta
    description, cornerstone flag, robots (noindex / nofollow / advanced), canonical,
    breadcrumb title, Open Graph + X/Twitter overrides, schema page/article type, and
    (posts) primary terms.
- **Search appearance** (`wpseo_titles`): `yoast/get-search-appearance` reads the title
  separator, homepage / special-page / per-content-type / per-taxonomy title & meta
  templates, noindex toggles, schema defaults, breadcrumbs, and the Knowledge Graph
  (organization vs person).
- **Social** (`wpseo_social`): `yoast/get-social-settings` reads Open Graph / X-Twitter
  toggles, card type, social profile URLs, the default and front-page social images.
- **General** (`wpseo`): `yoast/get-general-settings` reads feature toggles, webmaster
  verification codes, site representation, and crawl-cleanup options.
- **Write any setting:** `yoast/update-settings` takes a `{key: value}` delta and routes
  each key to its owning Yoast option group (wpseo / wpseo_titles / wpseo_social), saving
  through Yoast's validation. It reports `applied` (key → stored value) and `rejected`
  (unknown keys).
- **Introspection:** `yoast/list-replacement-variables` lists the `%%title%%` /
  `%%sitename%%` / `%%sep%%` … variables usable in title and meta-description templates.

Start with `yoast/find-content` to locate a post/term, `yoast/get-content-seo` to read it,
then `yoast/update-content-seo` to change it. For site-wide settings, read with the
`get-*` abilities (their keys are exactly the keys `yoast/update-settings` accepts).

## How it works (design)

Every mutation routes through Yoast's own canonical save path, so its sanitization,
validation, and indexable rebuilds run:

- **Post SEO** → `WPSEO_Meta::get_value()` / `set_value()`. Each `_yoast_wpseo_*` write is
  per-key, and Yoast's meta watcher rebuilds the post indexable at request shutdown.
  Primary terms (`_yoast_wpseo_primary_<tax>`) are written directly, as Yoast stores them
  outside `WPSEO_Meta`.
- **Term SEO** → `WPSEO_Taxonomy_Meta::get_term_meta()` / `set_values()`. Because
  `set_values()` resets absent text/social fields to their defaults, the adapter loads the
  **full** current term meta, overlays the delta, and persists the whole set — so a partial
  edit never wipes the other fields. It then forces a term-indexable rebuild via Yoast's
  `Indexable_Term_Watcher`, since the option write does not fire `edited_term`.
- **Settings** → `WPSEO_Options::get_option()` / `save_option()`. Each key is routed to its
  group by exact membership or Yoast's variable-key pattern table; the
  `sanitize_option_<group>` validate filter runs on save.

See `coverage/coverage-report.md` for the full surface/task map (and what's excluded and
why: Premium-only features like redirects, the import/export & file-editor tools, and the
SEMrush/Wincher/AI integrations that need external services).

## Layout

```
unofficial-abilities-for-wordpress-seo.php   main file — headers + bootstrap
bootstrap.php                                ACFW_Pack registry (categories + abilities)
abilities/                                   one file per group of abilities
  content.php          get / update / find content SEO (posts + terms)
  settings.php         get search-appearance / social / general + update-settings
  introspection.php    list-replacement-variables
src/Adapter/
  YoastStore.php       load-modify-save helpers, field maps, settings routing
coverage/
  inventory.json       structured understanding backing the coverage claim
  coverage-report.md   surface/task → ability (or excluded-with-reason) map
```
