Agent Connector for WP

Connect Claude — or any MCP-capable coding agent — to a WordPress site and give it real operational access: shell, WP-CLI, PHP eval, and the filesystem.

⚠️ Dangerous by design — trusted dev/staging only, never production.

What it does

WordPress' MCP stack exposes structured abilities, but agents still can't operate the server. Agent Connector for WP closes that gap: it registers operational abilities and surfaces them over MCP, then hands you a one-click way to connect an agent to them.

Abilities

Shell

Run arbitrary shell commands, capturing stdout, stderr, exit code — with cwd and timeout.

WP-CLI

Run any wp command against the install; --allow-root is added automatically when needed.

PHP eval

Evaluate PHP inside the live WordPress runtime; get back output, the return value, and errors.

Filesystem

Read, write, delete, and list files — binary-safe via base64.

Environment

Inspect versions, paths, active plugins/theme, debug flags, and available CLI tooling.

Process

Longer-running command execution, the forward-looking home for async/streaming control.

One-click connect

A Connect admin page generates everything an agent needs in one click: it mints a WordPress application password, computes the MCP endpoint, and hands you three copy-paste artifacts.

  • A natural-language prompt to paste into any coding agent
  • A claude mcp add command for Claude Code
  • An mcpServers JSON block for client config files

All three drive the @automattic/mcp-wordpress-remote proxy and authenticate with the application password.

Install

It's a monorepo — the plugin lives in plugin/. For local development, symlink it into your WordPress install:

git clone https://github.com/soflyy/agent-connector-for-wp.git
cd agent-connector-for-wp

# Install the plugin's PHP dependencies
( cd plugin && composer install --no-dev )

# Symlink plugin/ into wp-content/plugins/agent-connector-for-wp
bin/install.sh /path/to/wp-content

wp plugin activate agent-connector-for-wp

Then enable it in wp-config.php with define( 'AGENT_CONNECTOR_FOR_WP_ENABLED', true );. The plugin refuses to run on production unless explicitly overridden. Prefer a packaged release .zip? It already bundles dependencies — just activate.

Read this first

This plugin is intentionally unrestricted. Anyone holding a generated application password can run shell commands, evaluate PHP, and read/write files on the server as you. There is no sandboxing, no command allowlist, no approval workflow. Install it only where you would be comfortable handing out a root shell, and revoke application passwords when you're done.
